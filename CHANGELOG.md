## [Unreleased]

### Added

- **The app's own browser**: the agent now drives a pinned Chrome for Testing build that the app downloads (once, about 200 MB), launches only when the AI is called (or from **Open the browser** in Settings), watches and shuts down with the app. Persistent profile with cookies only, orange theme and icon, single app instance, minimum 1200x800 viewport before every tool.
- **Browser tools over MCP** (`claudia` server): `browser_open`, `browser_read`, `browser_text`, `browser_click`, `browser_type`, `browser_key`, `browser_scroll`, `browser_crop`, `browser_click_at`, `browser_upload`. Every read ends with an `estado:` line (ok, login_wall, captcha, vazio, carregando) and a repeated-call hint.
- **Send guard in app code**: a button that sends the application needs `confirm_submit` with the id of the single job in `candidatando`, within the daily budget, once per job per day. Any button that submits a form and is not a navigation step ("Next", "Back"...) also needs the confirmation. Works for click, Enter, Space and click-by-coordinate.
- **Native dialogs** (`alert`, `confirm`, `prompt`, `beforeunload`) are answered by the app so a page can never freeze the tab, and a crashed tab is reported to the agent.
- **Activity log**: always on, separate database, before/after screenshots, navigation history and the browser's own events (download, install, launch, crash, tab crash, dialog); 30 days or 1 GB retention; read-only screen under Settings.
- **Attach a resume**: a document library for resumes and cover letters in `<app data>/documentos/` (generated by the app or imported PDF/DOCX), a **Résumés** tab with an A4 grid and document page, tags, preferred document overall and per search variant, PDF generated by the app's own WebView2, and `browser_upload`, where the app (never the model) chooses the file.
- **Document and variant tools** for the agent: `list_documentos`, `get_documento`, `save_cover_letter`, `list_variantes`, `get_variante`, `set_vaga_variante`. `update_variante` and `set_documento_preferido` are refused in the execution session.
- A Windows Sandbox test lab in the repository (`sandbox-lab/`, skill `claudia-teste-sandbox`) with declarative environments, so tests that delete files run only inside the Sandbox.

### Changed

- The execution session runs `claude --no-chrome`; it waits for the app's browser instead of the Claude in Chrome extension.
- Cover letters refuse a profile without a name, warn when there is no e-mail and use a title in the letter's language.
- Old generated resumes and cover letters are migrated into the library on startup (once; the originals are kept).

### Removed

- The Claude in Chrome extension requirement and the native messaging host: no browser extension to install.
- The throwaway Playwright prototype (`prototipo-playwright/`); its conclusions live in `docs/pesquisa/`.

## [0.1.0] - 2026-06-23

### Added

- **Phase 1 — PTY shell**: Embedded terminal via `portable-pty` + `xterm.js` with ConPTY backend; locked/unlocked toggle for manual control
- **Phase 2 — Persistent state**: SQLite schema for jobs, applications, sessions, and pending items; `candidate_base.yaml` + `search_variants.yaml` profile model; `strategy.md` persistence
- **Phase 3 — Credential management**: Windows Credential Manager integration via `keyring` v3; credentials never stored in plaintext or passed through the terminal
- **Phase 4 — Session triggering**: Manual trigger button; idle detection via Win32 `GetLastInputInfo`; configurable threshold and daily budget; auto-trigger toggle
- **Phase 5 — Real session invocation**: `claude --dangerously-skip-permissions --chrome` spawned inside the PTY; system prompt built from profile + strategy + memory summary; `SESSION_CHECKPOINT_REQUESTED` signal detection and auto-relaunch; Chrome extension reconnect retry logic
- **Phase 6 — Pending items and notifications**: Windows toast notifications for unresolved pending items; configurable repeat interval; `PendenciaCard` with inline resolution, skip action, and captcha special case; click-to-navigate to Pending tab
- **Phase 7 — Dashboard and history**: Job history with status filter and application history sub-views; evolution proposal indicator; real-time updates via SQLite watcher events
- **Phase 8 — Conversational profile tab**: Chat-based profile editing via `claude --print`; bubble UI with inline markdown, streaming cursor, and section-focused edit mode; `EmptyState` onboarding with CV paste / file import / GitHub import; search variant management with normalized weight bars
- **Phase 9 — Feedback tab**: Deterministic data aggregation from SQLite; trend chart (SVG polyline, 30 days) and horizontal bar charts by result and variant; manual result marking; feedback generation trigger with milestone suggestions; sidebar dot indicator
- **Design system**: 13 color tokens + Inter typeface in `src/styles/tokens.css`; glasses logo; sidebar navigation with pending badge
